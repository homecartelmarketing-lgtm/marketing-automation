# Decision: Room Reveal Reel — one locked angle, empty-to-full build-up with an outro (2026-10-26)

New pipeline (`generate_room_reveal_reel_pipeline.py`, Studio Reel subtab 12 "Room
Reveal") recreating the client's reference MP4.

## Choices and why

- **One locked camera angle, not two.** The first design re-angled the room halfway
  through the reel. The client rejected it: the camera "must stay put", the only
  thing that may change is the room filling or emptying. So the reel is one room, one
  angle, and every edit is a subtraction from the previous result.
- **The stills are generated by removal but play in reverse.** Krea + the blend give
  `Full`, and Nano Banana Pro removes layer by layer down to `Empty`; the video then
  plays `Empty → Layer 1 → Layer 2 → Full` with frame counts `(24, 20, 20, 36)` = 100
  frames = 3.33 s. An earlier build played this as a boomerang (`Full → Empty → Full`,
  4.8 s); after reviewing it the client asked for the reveal to start on the empty room
  and build up to the finished photo. Reversing the same stills costs nothing — no
  second generation run. `Empty` holds 24 frames (0.8 s) at the open and `Full` holds
  36 frames (1.2 s) so the finished blend is what the viewer remembers.
- **The outro card is Final-Video only.** `assets/outro_layout.jpg` (1080x1920, the same
  card Virtual Staging ends on) is appended as a 75-frame (2.5 s) segment, giving a
  5.83 s Final Video. `Raw Video` stays the silent, outro-less build-up so the two
  deliverables stay clearly separated. A whoosh marks the card's entrance at 3.33 s;
  pops land on each layer cut.
- **The removal chain starts from the blend, never the Krea interior.** Otherwise
  the fixture itself would never leave the room, which was the whole point of the
  reference video. `prev_path`/`prev_url` are seeded with the Phase 4 blend.
- **Camera lock is enforced twice.** Every removal prompt carries
  `KEEP_IDENTICAL_SUFFIX` (tripod, same angle/perspective/framing/walls/floor/
  ceiling/lighting), and `evaluate_removal_step` rejects an attempt that drifts
  below `MIN_STEP_SIMILARITY = 0.72` on a blurred 48x85 grayscale comparison. The
  prompt asks the model; the local check verifies it.
- **Reused the Room Build-Up helpers instead of bolting a mode onto it.** Room
  Build-Up is hard-coded to two rooms with per-room fields (`ROOMS=(1,2)`), so a
  new monolith importing `assemble_hard_cut_video`, `ensure_sfx_assets` and
  `mix_sound_track` was cheaper and safer than a third execution mode. The shared
  `assets/room_buildup_sfx/` pop/whoosh cache is reused as-is.
- **Fields are provisioned by the pipeline, the table was created by hand.** Creating an
  Airtable table changes shared state and needs schema scope, so the client created
  `tbldk5nac1UeYHd77` and `_ensure_schema` added the 21 columns it needs (`Status` kept its
  `Standby`/`In progress`/`Complete` choices; `Done`, `For Manual` etc. are typecast-created on
  the first write). The field list is in `REQUIRED_FIELDS`; the Airtable API cannot PATCH
  single-select choices, which is why `ensure_single_select_options` only guarantees the field
  type and lets writes add options.
- **Bypass cost.** One row = 1 Krea + 1 Claude blend prompt (measurement-aware,
  scale-guarded blend) + 1 Claude removal plan + 3 removals (up to 9 with
  retries). No video model is used; the assembly and the outro are local FFmpeg.
